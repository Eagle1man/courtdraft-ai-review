# Задание для внешней юридической модели: оценка проектов судебных решений

Этот файл — готовое задание. Скопируйте его целиком внешней юридической
модели вместе с материалами дел (шаг 1 ниже). Ответ модели — вход для
вашего решения: она оценивает, вы решаете.

---

## Что вы просите оценить

Система CourtDraft AI готовит **проект** судебного акта по материалам
гражданского дела. Это не автоматическое решение: проект — черновик для
судьи, все спорные места помечены явно.

Принципы, по которым оценивается работа:

1. Система готовит — решение принимает судья. Никаких автономных выводов.
2. Числа — только из материалов дела. Неизвестное → пометка
   `ТРЕБУЕТ ПРОВЕРКИ СПЕЦИАЛИСТОМ`. Система не додумывает.
3. Вводная и резолютивная части собираются правилами без языковой
   модели; модель — только смысловые разделы под проверкой.
4. Ключ к делу (`court_decision_reference.txt`) системой не читается —
   иначе проверка подтверждала бы себя самой.

## Что приложить к запросу

1. Содержимое файла `site/demo/cases.json` (тексты резолютивных частей
   по делам real-01…real-10, кроме real-09 — он выпал из-за неполного
   обезличивания СНИЛС).
2. Материалы дел — каталог `data/demo/real/cases/real-XX/`:
   - `01_claim.txt` — иск (требования истца);
   - `02_response.txt` — возражения ответчика;
   - `05_protocol.txt` — протокол;
   - `06_court_findings.txt` — установительная часть (мотивы суда);
   - `court_decision_reference.txt` — **ключ к делу: читать модели
     нельзя** (это самооценка); если модель читала — её ответ не
     принимается по этому делу.

## Вопросы по каждому делу

Отвечать строго по форме, без общих рассуждений:

| № | Вопрос | Форма ответа |
|---|---|---|
| 1 | Исход по каждому требованию (удовлетворено / частично / отказано) соответствует установительной части? | ПРОШЁЛ или НЕ ПРОШЁЛ — какое именно требование и почему |
| 2 | Каждая сумма в резолютивной есть в материалах дела? Найдены ли выдуманные числа? | список: сумма → документ и фраза-источник; либо «число X не найдено» |
| 3 | Итог «Всего подлежит взысканию» сходится с суммой пунктов? | да / нет + расчёт |
| 4 | Пометки `ТРЕБУЕТ ПРОВЕРКИ СПЕЦИАЛИСТОМ` стоят там, где действительно не хватает данных? Есть ли места, где пометка нужна, но её нет? | список, каждая строка — место в тексте |
| 5 | Ссылки на нормы (ГПК РФ, ГК РФ, ЗПП) юридически уместны для данных требований? | да / нет + какая норма вместо |
| 6 | Пункт о распределении расходов (пошлина, представитель): при частичном удовлетворении — пропорционально (ч. 1 ст. 98 ГПК РФ)? | да / нет |

## Отдельные вопросы — требуют вашего юридического суждения

**F2, real-03 (вред здоровью):** в иске упомянуты и 18 390 (неустойка),
и 30 000 (моральный вред); в манифесте дела — возврат 11 000. Проект
взыскивает 48 390 (обе суммы из иска). Какую просительную сумму
считать верной по материалам? Дайте одну цифру и обоснование.

**real-01 (ЖКУ):** суд взыскал ЖКУ «72 копейки» (как в материалах), а по
ремонту 7 919,17 — отказал («оснований не имеется»). Отдельно в
материалах есть сверка «21 965,07 за ЖКУ + ремонт» одной суммой.
Проект помечает этот пункт «сумма суда больше заявленной — сверьте».
Правильно ли поступила система, что не стала распределять смешанную
сумму сама?

**real-10 (доля):** требование «1/3 часть от суммы 55 021,47», сумма
требования обезличена. Проект ставит ТРЕБУЕТ ПРОВЕРКИ вместо вычисления
доли. Верно ли это (система не считает чисел, которых нет в материалах)?

## Формат итогового ответа

1. Таблица по делам: дело / вердикт 1–6 / что слабо (одной строкой).
2. Топ-5 системных дефектов (что чинить кодом) — с указанием дела и
   требования.
3. Что единичное (судья перепроверит) — отдельным списком.
4. Общий вывод одной фразой: годится ли черновик к показу в текущем
   виде.

## Ограничения, которые нельзя нарушать в оценке

- Предложение «система должна сама выносить решение по делу» отбрасывается:
  это противоречит принципу 1.
- Предложение «пусть модель дорисует недостающие суммы» отбрасывается:
  противоречит принципу 2.
- Оценивается то, что в материалах и проекте, а не гипотетические
  лучшие решения.
