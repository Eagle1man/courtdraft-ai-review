## Подтверждённые дефекты

**F1 (P1): извлечение требований теряет сумму иска в 3 делах из 10.**
В `01_claim.txt` сумма есть (проверено зондом: real-05 → «1000»,
real-08 → «10148», real-10 → «55021» дважды), манифест её знает, но
`extract_requirements` не выделяет ни одного денежного требования —
резолютивная часть выходит без сумм (итог 0). Воспроизведение:

```powershell
backend\.venv\Scripts\python.exe scripts\e2e_audit.py   # смотреть real-05/08/10
backend\.venv\Scripts\python.exe scripts\tmp_amount_probe.py  # суммы в иске есть
```

Для real-08 это тот самый случай «подмены сумм» из замечаний рецензента:
пошлина 416 извлеклась, основная сумма 10 148 — нет.

**F2 (НЕ ПРОВЕРЕНО): real-03 — система взыскивает 18 390, манифест 11 000.**
В иске есть и 11 000, и 18 390 (и другие суммы); какая из них просительная —
определяет человек. Система выбрала 18 390 со ссылкой на `01_claim.txt`.
Нужна ручная сверка с текстом требований; автоматического вывода не делаю.

## Проверки, которые дефектов не показали

- Ссылки в никуда (цитата на несуществующий файл дела): **0** по всем делам.
- Дубли пунктов резолютивной части: **0**.
- Арифметика «итог = сумма требований + пошлина»: сходится везде.
- Пробелы без маркера `ТРЕБУЕТ ПРОВЕРКИ СПЕЦИАЛИСТОМ`: **0**.
- Возражения без вопроса: вопрос `OBJECTIONS_UNADDRESSED` поднимается
  там, где возражения в деле есть (real-01 и др.).

## Ограничения проверки (честно)

- Демо-конвейер (`build_real_site.process`) строит и проверяет **только
  резолютивную часть**; вводная и мотивировочная в демо не строятся.
  Поэтому `00_case_info.txt`, `05_protocol.txt`, `06_court_findings.txt`
  не попадают в источники оперативной — это дизайн демо, а не потеря фактов.
  Для полного конвейера проверка по смысловым разделам — задача отдельная.
- Юридическая корректность исхода и норм сквозной проверкой не подтверждается
  и не опровергается — только воспроизводимые факты из цепочки.
- Оценка на 20–30 делах с юристом остаётся вне автоматизации (п. 78 разбора).
