## Что это за система

ИИ-помощник судьи: готовит **проект** судебного акта по материалам
гражданского дела. Принципы, которые нельзя ломать в предложениях:

1. **Система готовит — решение принимает судья.** Никаких автономных
   выводов по делу; статусы, пометки и человек в контуре обязательны.
2. **Числа — только из материалов дела.** Неизвестное → в тексте маркер
   `ТРЕБУЕТ ПРОВЕРКИ СПЕЦИАЛИСТОМ`, никогда не додумывать.
3. **Правовые квалификации не выдумывать**: тайна совещания, сроки
   хранения, предмет доказывания для категорий без юридических перечней —
   вопросы специалисту, а не утверждения.
4. **Публикует только человек.** Материалы дел и PD не попадают в git.
5. **Юридическая техника:** вводная и резолютивная части собираются
   правилами без модели; модель — только смысловые разделы под надзором
   проверки (`app/verification`).

## Что осталось (потенциал для предложений)

- пропорциональность расходов при частичном удовлетворении (ч. 1 ст. 98)
  и возврат пошлины (ст. 333.40 НК) — механик нет;
- **вывод исхода дела из материалов**: механика `Outcome.PARTIAL/REFUSE`
  в `app/drafting/operative.py` есть, исход из материалов не выводится;
- предмет доказывания — 1 категория из многих (нужны юридические перечни);
- **эвристика извлечения суммы (F1) — частично закрыта** (`f74f6fb`, `124e5d4`):
  real-05/08 теперь извлекаются; осталось real-10 («1/3 часть от суммы» —
  пропорциональная доля остаётся в непознанных) и формат суммы прописью
  («20 921 (двадцать…) рубль»);
- **F2 (real-03)**: в проекте 48 390 (неустойка 18 390 + моральный вред
  30 000, обе из иска), в манифесте 11 000 (упоминание возврата) —
  просительную сумму определяет человек (фразы для сверы — в
  `docs/end-to-end-evaluation.md`);
- юридическая корректность не подтверждена: нужна оценка юриста
  на 20–30 делах (каркас — `docs/evaluation.md`);
- QD-Court: полезность направлений не размечена человеком — лист
  разметки готов (`data/eval/qd_labeling_sheet.md`, 43 строки: направления
  B и гипотезы C по 10 делам, шкала внутри); разметку делает юрист;
- признак ИП в карточке дела; подвал демо «синтетические материалы».

## Задача

1. **Ревью работы по второму ТЗ** (9 новых коммитов и `docs/agent-*.md`):
   открывайте код и запускайте скрипты, не верьте отчётам на слово.
   По каждому дефекту D1–D6/F1: `ПРОШЁЛ` / `НЕ ПРОШЁЛ — что именно слабо`.
   Доработку F1 (`f74f6fb`, `124e5d4`) проверяйте особенно: правки в
   `_without_fee_fragments` и логике обновления базы суммы — легко
   ослабить извлечение, сверяйте с тестами на живых делах.
2. **Ревью QD-Court** (`app/exploration/`): изоляция по делам, отсутствие
   влияния на акт, корректность кадров сравнения A/B/C.
3. **Слабые места**, которых нет в дефектах: архитектурные, правовые,
   по тестам (что тесты молча не проверяют), по обещаниям документации.
4. **Свой вариант доработки** — поэтапный план: приоритеты, что делает
   система, что остаётся человеком, объём этапа ≤ 1 дня. Предложения,
   нарушающие принципы 1–2 выше, отбрасывайте сразу.
