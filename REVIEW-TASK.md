# Ревью CourtDraft AI — задание для независимой модели

Снимок проекта «ИИ помощник судьи» (CourtDraft AI) на ветке
`feat/phase-6-10-api-docs`, локальное состояние на 2026-10-20: 20 коммитов.
Задача — оценить сделанное и предложить свой вариант доработки.

## Что это за система

ИИ-помощник судьи: готовит **проект** судебного акта по материалам
гражданского дела. Принципы, которые нельзя ломать в предложениях:

1. **Система готовит — решение принимает судья.** Никаких автономных
   выводов по делу; статусы, пометки и человек в контуре обязательны.
2. **Числа — только из материалов дела.** Неизвестное → в тексте маркер
   `ТРЕБУЕТ ПРОВЕРКИ СПЕЦИАЛИСТОМ`, никогда не додумывать.
3. **Правовые квалификации не выдумывать**: тайна совещания, сроки
   хранения, предмет доказывания для категорий без юридических перечней —
   вопросы специалисту, а не утверждения.
4. **Публикует только человек.** Материалы дел и PD не попадают в git.
5. **Юридическая техника:** вводная и резолютивная части собираются
   правилами без модели; модель — только смысловые разделы под надзором
   проверки (`app/verification`).

## Данные дел

Обезличенные судебные дела (`data/demo/real/`, 10 дел из открытого
учебного датасета HuggingFace `TryDotAtwo/russian-legal-ner`, обезличены
скриптом) и оценочная ведомость (`data/eval/eval_worksheet.md`)
**включены намеренно**: датасет публичный и учебный. Их можно читать и
ссылаться на них в ответе.

Также исключены: `.env`, кэши, индексы корпуса (гигабайты).

## Что осталось (потенциал для предложений)

- пропорциональность расходов при частичном удовлетворении (ч. 1 ст. 98)
  и возврат пошлины (ст. 333.40 НК) — механик нет;
- **вывод исхода дела из материалов**: механика `Outcome.PARTIAL/REFUSE`
  в `app/drafting/operative.py` есть, исход из материалов не выводится;
- предмет доказывания — 1 категория из многих (нужны юридические перечни);
- сквозная проверка на живых делах: покрытие доказательств, подбор норм,
  ответы демо-диалога по ключевым словам;
- сама оценка качества на 20–30 делах: каркас готов, заполняет юрист;
- признак ИП в карточке дела; подвал демо «синтетические материалы».

## Задача

1. **Ревью по 8 коммитам**: открывайте код, не верьте статус-документу на
   слово. По каждому пункту: `ПРОШЁЛ` / `НЕ ПРОШЁЛ — что именно слабо`
   (не «стоит доработать»).
2. **Слабые места**, которых нет в замечаниях рецензента: архитектурные,
   правовые, по тестам (что тесты молча не проверяют), по обещаниям
   README/документации.
3. **Свой вариант доработки** — поэтапный план: приоритеты, что делает
   система, что остаётся человеком, объём этапа ≤ 1 дня. Предложения,
   нарушающие принципы 1–2 выше, отбрасывайте сразу.
4. **Вопрос выбора**: брать следующим пунктом вывод исхода из материалов
   или сначала сквозную проверку на живых делах? С обоснованием.

## Формат ответа

- вердикт по 8 коммитам (таблица: коммит / вердикт / что слабо);
- топ-5 рисков системы в текущем виде;
- поэтапный план с приоритетами;
- одно предложение, которое вы сделали бы иначе «с нуля» — и стоит ли его
  брать.

Проверки (если есть среда): `cd backend && python -m pytest -q`,
`ruff check app tests`, `mypy --strict app` — ожидается 688 тестов, чисто.
