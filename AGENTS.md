# CourtDraft AI — правила работы с проектом

## Что это

Локальная система подготовки **проекта** судебного акта по материалам дела и
протоколу судебного заседания.

**Главный принцип продукта:**

> ИИ готовит проект. Человек проверяет и принимает решение.

**Главный принцип разработки:**

> Разрабатываем на CPU-only ноутбуке 8 GB RAM, запускаем реальную AI-модель
> на RTX 3050.

---

## Юридические ограничения (нарушение = баг, а не стилистика)

Эти правила не обсуждаются и не нарушаются ради удобства:

1. **Система формирует только ПРОЕКТ.** Никогда — готовый судебный акт.
2. **Не придумывать факты, доказательства, нормы права и судебную практику.**
   Нет источника → «ТРЕБУЕТ ПРОВЕРКИ СПЕЦИАЛИСТОМ».
3. **Каждое существенное утверждение имеет источник** (document_id, страница,
   абзац). Утверждение без источника — дефект.
4. **Нельзя создавать процессуальное событие, которого нет в протоколе.**
5. **Не отвечать за редакцию нормы, действовавшую на момент события**
   (п.16 ТЗ): проверять `effective_from` / `effective_to`.
6. **Нет автоматического утверждения решений.** Финальное действие — за человеком.
7. **В интерфейсе всегда** юридическое предупреждение (п.70 ТЗ).

Если выполнить требование нельзя, не выдумывая, — оставляем маркер
`ТРЕБУЕТ ПРОВЕРКИ` и идём дальше. Это правильный результат, а не недоделка.

## Режимы: MOCK и REAL

Переключение — **только через `.env`**. Код не должен содержать
`if mock:` в агентах.

| Переменная | Разработка (8 GB, CPU) | RTX 3050 |
|---|---|---|
| `LLM_PROVIDER` | `mock` | `ollama` |
| `EMBEDDING_PROVIDER` | `mock` | `local` |
| `OLLAMA_ENABLED` | `false` | `true` |
| `OLLAMA_MODEL` | — | `qwen3.5:4b` |
| `APP_ENV` | `development` | `runtime` |

**Правило:** агент работает только через `LLMProvider` / `EmbeddingProvider`.
Прямой вызов `ollama` или `httpx` к модели в агенте — нарушение архитектуры.

**Модель не зашивается в код.** Только через `.env`.

**Система обязана стартовать** при отсутствии модели эмбеддингов,
сообщая: `Embedding provider unavailable. System is running in degraded/mock mode.`

## Команды

```powershell
.\scripts\install.ps1    # окружение, зависимости, .env
.\scripts\start.ps1      # backend :8000, frontend :3000
.\scripts\stop.ps1       # остановить
.\scripts\health.ps1     # состояние компонентов
.\scripts\demo.ps1       # полный проход pipeline в MOCK (Фаза 16)
```

Внутри backend:

```powershell
cd backend
.venv\Scripts\python.exe -m pytest              # тесты
.venv\Scripts\ruff.exe check app tests          # линтер
.venv\Scripts\mypy.exe app                      # типы (strict)
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

### PowerShell: файлы в UTF-8 **с BOM**

Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI — кириллица
разъезжается и ломает парсинг. Скрипты проекта сохраняются **с BOM**.

В Python такой проблемы нет: файлы читаются как UTF-8.

## Правила разработки

1. **Одна фаза — один набор изменений.** Не смешивать.
2. **После каждой фазы:** тесты → линтер → типы → импорты → API → diff.
3. **Не оставлять `TODO`, `pass`, `NotImplementedError`, `fake`.**
   Либо функция работает, либо её нет. Исключение — объявление интерфейса
   с `...` в теле `Protocol`, это допустимо.
4. **Покрытие тестами обязательно** для бизнес-логики: агентов, verification,
   RAG, деградации. Новый код без тестов не завершён.
5. **Комментарии объясняют «почему», а не «что».** Особенно: почему выбран
   обходной путь, а не очевидное решение.
6. **Типы обязательны.** mypy в режиме `strict`.
7. **Комментарии и тексты в интерфейсе — по-русски**, код и имена — по-английски.
8. **Документы и дела не попадают в git.** `.env` тоже.

### Запрещено

- `git reset --hard`, `git clean -fd` без явного разрешения.
- Удалять существующий проект или чужие файлы.
- Добавлять зависимости вне `pyproject.toml` / `package.json`.
- Обращаться к облачным LLM или embedding API (п.44). Только локально.

## Безопасность и данные

- **LOCAL ONLY.** Никакого облака.
- Материалы дел — персональные данные. Не логировать содержимое документов,
  не класть в git, не отправлять наружу.
- В логах — идентификаторы и статусы, не тексты документов.
- Текст исключения возвращается клиенту только при `DEBUG=true`.
- PII-обезличивание обязательно для демо-данных (п.45).
  Regex — не защита production, это осознанное ограничение MVP.

## Git

- Ветка на фазу: `feat/phase-N-<короткое>`.
- Сообщения — по-русски, в прошедшем времени, с указанием фазы.
- Один логический блок — один коммит.
- Перед завершением фазы: `git status` и `git diff` должны быть чистыми
  относительно заявленного.

---

## Definition of Done (фаза)

Фаза завершена, только если выполнено **всё** из п.68 ТЗ:

- [ ] тесты проходят;
- [ ] ошибки исправлены, не заглушены;
- [ ] импорты чистые;
- [ ] API отвечает (`/api/health` не хуже DEGRADED по необязательным);
- [ ] `docker compose config` валиден, если compose есть в фазе;
- [ ] документация обновлена;
- [ ] `git diff` проверен.
