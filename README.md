# CourtDraft AI

> Локальная система подготовки **проекта** судебного акта по материалам
> конкретного судебного дела и протоколу судебного заседания.

## ⚠️ Юридическое предупреждение

CourtDraft AI формирует **проект** судебного акта на основании предоставленных
материалов. Система **не осуществляет правосудие** и **не принимает окончательных
судебных решений**. Проект подлежит обязательной проверке и редактированию
уполномоченным специалистом. Возможны ошибки и неполнота исходных данных.

---

## Принципы

**Продукт:**

> ИИ готовит проект. Человек проверяет и принимает решение.

**Разработка:**

> Разрабатываем на CPU-only ноутбуке 8 GB RAM. Реальная AI-модель запускается
> на RTX 3050 — без правки исходного кода.

## Как это устроено

```
Материалы дела → Факты → Доказательства → Протокол → Нормы права
    → Судебная практика → Evidence Pack → Проект акта
    → Автоматическая проверка → Проверка и редактирование человеком
```

Ключевое требование: **каждое существенное утверждение имеет источник**.
Утверждение без источника помечается как требующее проверки, а не выдумывается.

## Режимы

| | Разработка (ноутбук 8 GB, без GPU) | Запуск (RTX 3050) |
|---|---|---|
| `LLM_PROVIDER` | `mock` | `ollama` |
| `EMBEDDING_PROVIDER` | `mock` | `local` |
| `OLLAMA_MODEL` | — | `qwen3.5:4b` |
| `APP_ENV` | `development` | `runtime` |

Различие между машинами — **только в `.env`**. Код одинаковый.

Бизнес-логика не зависит от модели: агенты работают через интерфейсы
`LLMProvider` и `EmbeddingProvider`, у которых есть MOCK- и REAL-реализации.

## Установка и запуск

```powershell
git clone <repo> courtdraft-ai
cd courtdraft-ai

.\scripts\install.ps1    # проверки, venv, зависимости из pyproject.toml, .env
.\scripts\start.ps1      # backend на :8000, frontend на :3000
.\scripts\health.ps1     # состояние компонентов
```

Документация API: <http://localhost:8000/docs>

### Что требуется на машине разработки

- Python 3.12+ (проверено на 3.14)
- Node.js 20+
- Git

**Не требуется:** GPU, Ollama, Docker, реальная модель.

## Что работает сейчас (v0.1, фазы 1–4)

- репозиторий и структура проекта;
- конфигурация через `.env` с переключением MOCK/REAL;
- FastAPI-приложение с `/api/health`, `/api/info`, `/api/ready`;
- `LLMProvider`: `MockLLMProvider` + `OllamaProvider`;
- `EmbeddingProvider`: `MockEmbeddingProvider` + `LocalEmbeddingProvider` + деградация;
- 14 таблиц хранения: дела, документы, чанки с provenance, анализ,
  evidence, проекты и версии, проверки, нормы, практика, шаблоны, аудит;
- SQLAlchemy 2.0 async + репозитории + обратимая миграция Alembic;
- эндпоинты `POST /api/cases`, `GET /api/cases`, `GET /api/cases/{id}`,
  документы и участники;
- векторный поиск: dense + BM25 + RRF, три коллекции, payload-фильтры
  по метаданным (включая редакцию нормы на заданную дату);
- 166 тестов, `ruff` и `mypy --strict` зелёные;
- скрипты `install` / `start` / `stop` / `health`.

### Векторное хранилище и поиск

Qdrant работает в двух режимах — переключение одной переменной:

```env
QDRANT_MODE=memory    # встроенный клиент, сервер не нужен
QDRANT_MODE=server    # реальный Qdrant (RTX 3050)
```

В режиме `memory` работают векторы, payload-фильтры и поиск по сходству;
данные не переживают перезапуск — это режим разработки, не работа.

Почему dense + BM25, а не только dense: в юридических документах решают
точные совпадения — номера статей, даты, суммы. Их находит BM25, а RRF
объединяет оба списка **по рангам**: оценки косинуса и TF-IDF несопоставимы,
усреднять их бессмысленно.

### Честно о метриках

`backend/scripts/eval_retrieval.py` показывает Recall@5 = 1.000 на
синтетическом корпусе, но запросы там почти дословно совпадают с текстом
и находятся за счёт BM25. На перефразированных запросах Recall@5 = 0.00
(`eval_sanity.py`) — заглушка эмбеддингов не понимает смысл. Реальные
метрики RAG измеряются на RTX 3050.

### База данных

Код работает и с PostgreSQL, и с SQLite — переключение одной переменной
в `.env`. Это сделано потому, что на машине разработки PostgreSQL
установить нельзя (нет Docker, на C: 1.2 GB), а Фазы 3–10 нужно было
разрабатывать и тестировать сейчас.

```env
# разработка (по умолчанию, если DATABASE_URL пуст)
DATABASE_URL=

# RTX 3050
DATABASE_URL=postgresql+asyncpg://courtdraft:courtdraft@localhost:5432/courtdraft
```

Подробности и список диалект-специфичных решений — в

## Безопасность

- **Только локально.** Никаких облачных LLM и embedding API.
- Материалы дел не покидают машину и не попадают в git.
- PII-обезличивание для демо-данных. Regex — осознанное ограничение MVP,
  не production-защита.
